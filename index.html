source included Libft
Fatma-authored source snapshot

Objective

Rebuild useful libc routines and add linked-list helpers as a reusable static library.

Concepts, simply

Pointers are addresses; allocation reserves bytes; a header is the library's promise; a Makefile repeats the build safely.

Important functions

ft_strlen, ft_memcpy, ft_split, ft_itoa, ft_lstnew, ft_lstadd_back.

read header→compile .c → .o→archive libft.a→link + test
make cc main.c -L. -lft -o demo ./demo

Step by step

  1. Write the contract in libft.h.
  2. Handle empty input and integer limits first.
  3. Allocate only when the caller owns the result.
  4. Use make to rebuild after one change.

Tests + mistakes

Compare strings with libc, test NULL/empty/huge input, and run a leak checker. Reserve space for \0; free partially built arrays; never return freed memory.

What I learned

Small contracts and ownership rules make later projects dramatically easier.

source included Cub3D
Fatma-authored game-engine snapshot · MiniLibX excluded

Objective

Turn a text map into a small ray-casting game with textures, movement, and collision.

Concepts

Parsing, flood validation, DDA ray casting, distance correction, textures, keyboard hooks, collision.

Important functions

.cub parser, map validator, ray stepper, wall-column renderer, texture sampler, movement/collision hooks, cleanup.

read .cub→validate map→cast DDA rays→draw columns→input + collide
make ./cub3D maps/test.cub

Step by step

  1. Parse textures, colors, and the player exactly once.
  2. Flood-check that walkable cells are enclosed.
  3. Cast one ray per screen column.
  4. Use DDA to find the first wall and correct fish-eye distance.
  5. Draw, process input, then free images before exit.

Test + mistakes

Try open edges, missing textures, duplicate directives, diagonal gaps, collision corners, and window close. Mixing degrees/radians and freeing MiniLibX objects in the wrong order are common failures.

Lesson

A reliable parser and coordinate model are the foundation of a convincing real-time display.

source included Minitalk
Fatma-authored source snapshot

Objective

Send text from a client process to a server using only Unix signals.

Concepts

PIDs, SIGUSR1/SIGUSR2, bit encoding, acknowledgements, async-signal safety.

Important functions

Server signal handler, client bit loop, byte reconstruction, PID validation, and optional acknowledgement path.

char → bits→SIGUSR1/2→server rebuilds byte→ACK
make ./server ./client <server-pid> "hello 42"

Step by step

  1. Validate the PID.
  2. Send the highest bit first.
  3. Shift received bits into a byte.
  4. Print after eight bits and reset state.
  5. Acknowledge so the client cannot outrun the server.

Test + mistakes

Try empty/long/byte sequences and invalid PIDs. Unsafe handler calls, timing races, lost final bytes, and missing NUL termination are the classic traps.

Lesson

Even a two-signal channel needs an explicit protocol.

source included Minishell
Fatma-authored implementation snapshot

Objective

Create a Bash-style shell with built-ins, quoting, expansion, pipelines, redirections, heredocs, signals, and process control.

Concepts

Lexing/parsing, environment ownership, fork/execve/waitpid, file descriptors, signal modes, cleanup.

Important functions

Tokenizer/syntax helpers, expansion, built-in dispatch, pipe setup, redirection, heredoc reader, status propagation, free-all cleanup.

readline→tokens + syntax→expand→pipes/redirs→builtin or execve→wait + free
make ./minishell make bonus && ./minishell_bonus

Step by step

  1. Read one line without mutating the environment.
  2. Reject malformed operators before execution.
  3. Expand variables/wildcards with quote rules.
  4. Create FDs and children only after parsing.
  5. Restore signals, collect statuses, and free every owner.

Test + mistakes

Compare each command with Bash: quotes, empty expansions, pipes, >>, heredocs, Ctrl-C/Ctrl-D, invalid commands, and exit status. Leaking FDs or child memory causes flaky behavior.

Lesson

A shell is a compiler pipeline plus a process supervisor.

lesson Philosophers
Lesson included · local reference tree includes Theo Guérin headers

Objective

Simulate philosophers sharing forks without races, deadlocks, starvation, or inaccurate timing.

Concepts

POSIX threads, mutexes, monitor thread, timestamps, fairness, coordinated shutdown.

Important functions

Argument parsing, philosopher routine, fork lock order, meal timestamp update, death monitor, mutex destruction.

parse rules→create forks/threads→eat/sleep/think→monitor→stop + destroy

Build + use
